# 隱私與本機設定

## 應用程式處理的資料

病歷文字、表單與判讀結果保留在應用程式記憶體，未由本程式自動寫入病歷檔案或傳送至遠端服務。程式不需 API Key、帳號或資料庫，也不自動連線更新給付規則。

使用者按「複製摘要」後，摘要進入作業系統剪貼簿；作業系統的剪貼簿歷程、同步、螢幕擷取及其他軟體行為不受本程式控制。點選回饋網址會開啟外部 Google 表單，適用該服務政策；不要填入病人識別資料。

v1.2.4 的摘要包含暫定分級標記、待補欄位及判讀提醒，避免離開程式後遺漏複核條件。無效數值停止判讀時會清除畫面上的舊結果，但不會自動清除系統剪貼簿中先前已複製的內容；貼入其他系統前仍須核對版本與內容。

這些說明不代表整台電腦絕不保存資料。請依機構規範選擇可輸入的資訊，並在共享電腦上注意剪貼簿與檔案權限。

## 統一設定檔

原始碼版本使用專案根目錄的 `Statin_NHI_available.json`；EXE 使用同資料夾的檔案。設定只含院內代碼與提醒偏好，不需病人資訊：

```json
{
  "medication_codes": [],
  "dismissed_updates": {
    "1150672925": true
  }
}
```

`medication_codes` 可為空；`dismissed_updates` 也可省略以相容舊版。`true` 代表已關閉該文號的提醒。空白範例位於 `examples/`，切勿覆蓋正在使用的院內設定。

啟動時，新增 6 項任一代碼已存在就視為本次已設定，不再提醒；全部未設定才顯示名單。關閉提醒與儲存藥物清單會保留彼此欄位。設定格式錯誤或無法寫入時，應先備份修正，不要刪除原檔後盲目重建。

## 舊版提醒遷移

舊 `Statin_NHI_reminders.json` 與統一設定檔放在同資料夾時，讀取到的有效提醒紀錄會合併；統一檔既有鍵值優先。原檔保留，成功確認統一檔已有紀錄後可自行移除。若無法寫入，舊檔仍可作為提醒判斷來源；不要在未確認前刪除。

## 公開協作資料

院內 JSON、EXE、環境憑證及真實病例不能加入 Git。測試案例及檢驗表格由維護者確認為人工編造，只用於程式回歸，不代表真實病人資料或外部臨床驗證。

不要在 Issue／PR 上傳真實姓名、病歷號、身分證字號、生日、聯絡方式、病歷截圖或未經許可的院內文件。需要重現問題時，請改寫為完全人工編造且最小化的輸入。
